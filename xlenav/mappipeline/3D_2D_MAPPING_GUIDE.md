# 3D-2D Coordinate Mapping Guide

This guide explains how to use the transformation parameters generated by `autoprojector.py` to perform interactive mapping between 3D point cloud coordinates and 2D occupancy map grid coordinates.

## Overview

When you generate a 2D occupancy map from a 3D point cloud, the system now saves all the necessary transformation parameters that allow you to:

1. **Convert 3D world coordinates → 2D grid coordinates** (for visualization, path planning)
2. **Convert 2D grid coordinates → 3D world coordinates** (for robot navigation, object placement)
3. **Interactive applications** (click on 2D map to highlight 3D location, and vice versa)

## Files Generated

When you run `autoprojector.py`, it generates three files:

```
xlenav/
├── occupancy_map.pgm              # 2D occupancy grid image
├── occupancy_map.yaml             # ROS-compatible metadata
└── occupancy_map_transform.npz    # 3D-2D transformation parameters (NEW!)
```

The point cloud data is read from:
```
xlenav/mappipeline/sparse1/points.ply
```

### Transformation Parameters Saved

The `*_transform.npz` file contains:

| Parameter | Description |
|-----------|-------------|
| `ground_plane_normal` | Normal vector of the ground plane [a, b, c] |
| `ground_plane_d` | Plane constant (ax + by + cz + d = 0) |
| `plane_basis_u` | First basis vector of the 2D coordinate system on the plane |
| `plane_basis_v` | Second basis vector of the 2D coordinate system on the plane |
| `plane_origin` | Origin of the 2D coordinate system in 3D world space |
| `grid_x_min`, `grid_y_min` | Minimum bounds in local plane coordinates |
| `grid_x_max`, `grid_y_max` | Maximum bounds in local plane coordinates |
| `resolution_measured_units` | Grid resolution in COLMAP measured units |
| `resolution_meters` | Real-world resolution (default: 0.05 m/pixel = 5 cm) |
| `scale_factor` | Conversion factor: meters/unit |
| `grid_width`, `grid_height` | Dimensions of the occupancy grid in pixels |

## Usage Examples

### 1. Basic Usage with MapTransformer

```python
from map_transformer import MapTransformer
import numpy as np

# Load transformation parameters
transformer = MapTransformer.from_file('xlenav/occupancy_map_transform.npz')

# Print transformation info
print(transformer.get_info())

# Convert 3D point to 2D grid coordinates
point_3d = np.array([1.5, 2.3, 0.8])
grid_x, grid_y = transformer.world_to_grid(point_3d)
print(f"3D point {point_3d} → Grid ({grid_x}, {grid_y})")

# Convert 2D grid coordinates to 3D point (on ground plane)
grid_x, grid_y = 100, 150
point_3d = transformer.grid_to_world(grid_x, grid_y)
print(f"Grid ({grid_x}, {grid_y}) → 3D point {point_3d}")

# Get real-world coordinates in meters
x_meters, y_meters = transformer.grid_to_world_meters(grid_x, grid_y)
print(f"Grid ({grid_x}, {grid_y}) → ({x_meters:.3f}, {y_meters:.3f}) meters")
```

### 3. Integration with Path Planning

```python
from map_transformer import MapTransformer
import numpy as np

# Load transformer
transformer = MapTransformer.from_file('xlenav/occupancy_map_transform.npz')

# Assume you have a 2D path from A* or other planner
path_2d_grid = [
    (50, 50),   # Start
    (55, 60),
    (60, 70),
    (70, 90),   # Goal
]

# Convert to 3D waypoints for robot navigation
path_3d_waypoints = []
for grid_x, grid_y in path_2d_grid:
    point_3d = transformer.grid_to_world(grid_x, grid_y)
    path_3d_waypoints.append(point_3d)

print(f"Generated {len(path_3d_waypoints)} 3D waypoints from 2D path")
for i, wp in enumerate(path_3d_waypoints):
    print(f"  Waypoint {i}: {wp}")
```

            point_3d = self.transformer.grid_to_world(grid_x, grid_y)

## Mathematical Details

### 3D to 2D Transformation

```
1. Project 3D point to ground plane:
   projected = point_3d - (n·point_3d + d) * n

2. Convert to local plane coordinates:
   relative = projected - origin
   u = relative · basis_u
   v = relative · basis_v

3. Convert to grid coordinates:
   grid_x = floor((u - grid_x_min) / resolution)
   grid_y = floor((v - grid_y_min) / resolution)
```

### 2D to 3D Transformation

```
1. Convert grid to plane coordinates (use pixel center):
   u = grid_x_min + (grid_x + 0.5) * resolution
   v = grid_y_min + (grid_y + 0.5) * resolution

2. Convert to 3D world coordinates:
   point_3d = origin + u * basis_u + v * basis_v

3. Project to ground plane (ensures point is exactly on plane):
   point_3d = point_3d - (n·point_3d + d) * n
```

## API Reference

### MapTransformer Class

#### Methods

- **`from_file(npz_path)`**: Load transformation parameters from NPZ file
- **`world_to_grid(point_3d)`**: Convert 3D point to 2D grid coordinates
- **`grid_to_world(grid_x, grid_y)`**: Convert 2D grid to 3D point on ground plane
- **`world_to_plane_coords(point_3d)`**: Convert 3D to local 2D plane coordinates
- **`plane_coords_to_world(u, v)`**: Convert local 2D plane coords to 3D
- **`grid_to_world_meters(grid_x, grid_y)`**: Get real-world 2D coordinates in meters
- **`world_meters_to_grid(x_meters, y_meters)`**: Convert meters to grid coordinates
- **`project_point_to_plane(point)`**: Project 3D point onto ground plane
- **`get_info()`**: Get human-readable transformation information

## Notes and Limitations

1. **All 3D points are projected to the ground plane** - The Z coordinate in the returned 3D points represents the height of the ground plane, not the original point height.

2. **Grid bounds** - Points outside the grid bounds will return (-1, -1) for grid coordinates.

3. **Resolution** - The default resolution is 5cm per pixel (0.05 m). This can be adjusted in the configuration.

4. **Coordinate systems**:
   - **3D World**: COLMAP coordinate system (arbitrary units before scaling)
   - **2D Plane**: Local coordinate system on the ground plane (origin at plane centroid)
   - **2D Grid**: Pixel coordinates (0,0) at top-left, Y-axis points down
   - **Real-world**: Meters, scaled using camera-ground distance

## Troubleshooting

### Points appear in wrong location

- Check that you're using the correct transformation file for your map
- Verify scale_factor is correct (check camera-ground distance in config)

### Grid coordinates are (-1, -1)

- Point is outside the mapped area
- Check grid bounds with `transformer.get_info()`

### 3D visualization doesn't match 2D map

- Ensure you're using the same point cloud used to generate the map
- Check that the ground plane was fitted correctly
